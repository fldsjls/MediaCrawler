# 2026-09-07 原生预览功能验收

> 文档类型：历史执行快照；本页记录本地功能和生命周期，不把通过项目数当作帧率结果。
> 路径：工作台当前 `NativeRTCStreams` 与 Chromium 原生标签页捕获；使用独立临时 Profile 和本地网页样本，没有真实平台认证或采集。

## 独立生命周期

通过项目的 `BrowserSession.rtc.offer` 接口连接真实 Chromium 接收页面，使用颜色标记核对捕获对象，使用小目标及输入框验证操作。最后一次脚本退出码为 0，以下 7 组通过：

| 检查 | 结果 |
| --- | --- |
| 当前页面捕获 | 解码 1280×720，颜色标记与所选原始页面一致 |
| 辅助页隔离 | 不进入公开列表；以真实辅助页身份构造的媒体请求被公共捕获器拒绝 |
| 同页导航和刷新 | 同一 peer 恢复新页面画面，24 像素小目标点击及前后中文输入通过 |
| 弹出页面 | 选择新页面后重连正确目标，滚轮实际改变页面滚动位置 |
| 隐藏与低刷新 | 最后一个 peer 释放辅助页，JPEG 复用同一 PID，末个订阅退出后停止生产者 |
| 普通 HTTP | 不具 CaptureHandle 的本地模拟 HTTP 域名被明确拒绝实时捕获，不传输无法验证的目标 |
| 会话关闭 | 所属浏览器进程结束 |

原始脚本为 `%TEMP%/mediacrawler-native-lifecycle-audit.py`，最终报告为 `%TEMP%/mediacrawler-native-lifecycle-audit.json`。脚本约 26 秒，记录阶段与捕获状态时间线，不测持续帧率。辅助页媒体检查使用真实 Page 身份和合成 Request，避免“请求被 CSP 拦截所以没有候选”掩盖媒体层缺少过滤的错误。

前两次复测在导航后发现实时 peer 已因尺寸变化关闭；当时源 DOM 已是 1280×720，仍不能仅凭 DOM 推断捕获尺寸正确。修复加入暂停、物理内容区重新对齐和身份复核。最终时间线观察到导航时暂为 1186×720，`needsIdentity` 持续为真；恢复 1280×720 并复核后才恢复画面。同页刷新也通过。

本地测试 HTTP 服务在客户端退出时记录过一次连接重置，这是样本服务的请求关闭日志；应用流程检查通过，最终进程清理完成。

## 六组界面矩阵

隔离 API/Profile 下验证 1440×900、1366×768、390×844，各含浅色和深色，共 6 组通过。检查原生 1280×720 视频、同会话中文输入、实时与低刷新切换、隐藏恢复、导航折叠或抽屉，以及没有页面横向溢出。控制与资源连接分别保持 1 个；实时、低刷、隐藏分别对应 1 个 peer、1 个 JPEG 连接、无画面连接。页面错误列表为空，所属源进程结束。

证据位于 `%TEMP%/mediacrawler-native-ui-six-9seje0nx/` 的桌面报告及 4 张截图，以及 `%TEMP%/mediacrawler-native-ui-six-tfauvr92/` 的手机报告及 2 张截图。首轮手机仅遇到测试定位器同名“关闭导航”按钮歧义，限定主导航后补跑通过。此矩阵不测 FPS；其中导航检查是工作台导航保留会话，同一网站标签页跳转由上面的独立生命周期另验。

## 边界

功能通过不表示工作台持续达到至少 30 帧/秒。60 帧/秒是当前新会话的配置目标；生产性能应以独占测量报告为准，不能引用[独立原生捕获实验](2026-09-07-preview-route-comparison.md)的约 55.94 帧/秒替代。

HTTPS、本机页面的通道测试不代替真实网站登录、加载、验证码、媒体捕获和下载验收。普通 HTTP 的身份 API 限制仍存在；美石建工当前 HTTP 入口按低刷新边界使用。当前结构见[浏览器架构](../architecture/browser-workspace.md)，后续性能与功能测试遵循[验收方法](../development/quality.md)。
