# 2026-09-07 实时预览路线比较

> 文档类型：历史实验与集成阶段快照
> 环境：Windows 本机纯网页；样本和测量时点不同，不把单次最佳值作为稳定性能。

用户验收目标为人工接管达到至少 30 帧/秒，自动采集切换低刷新，同时保持同一浏览器和纯网页交付。下面区分旧传输路径的生产测量与原生标签页捕获的独立实验。

## 已记录的样本

| 路径与阶段 | 接收端结果 | 结论 |
| --- | --- | --- |
| 独立 CDP → JPEG → Python RTC，VP8 | 33 帧 / 10.031 秒，约 3.29 帧/秒 | 未达到人工接管目标 |
| 同类路径改用 H.264 的一次测量 | 103 帧 / 10.031 秒，约 10.27 帧/秒 | 单次结果，不能称稳定达到此值 |
| 随后的生产路径复测 | 64 帧 / 10.125 秒，约 **6.32 帧/秒** | 后续测量回落，不能挑选 10.27 作为最终结论 |
| 原生标签页捕获独立样本 | 560 帧 / 10.0113 秒，约 **55.94 帧/秒**，最低分段约 50.98 帧/秒 | 独立样本证明候选路径有性能空间；当时尚未完成工作台生产集成验收 |

前三次原始报告位于 `%TEMP%/mediacrawler-install-check/`：`rtc-performance-direct-cdp-results.json`、`rtc-performance-h264-results.json`、`rtc-performance-production-results.json`。原生报告为 `%TEMP%/mediacrawler-tab-capture-experiment/native-tab-capture-precise-results.json`：Chromium 149.0.7827.55、headless-new、1280×720，使用 capture handle 和像素标记核对指定标签页，独立样本也记录了点击和中文输入。生产接入和实际网站验证需要另行记录。

生产路径复测的低刷新结果为 15 帧 / 10.047 秒，约 1.49 帧/秒；五次点击到页面 HTTP 回执为约 344 / 1219 / 640 / 938 / 3094 毫秒。回执时间不是点击到画面呈现的端到端响应延迟。

## JPEG 直传候选的诊断样本

另一个独立试验去掉 Python 视频转码，直接把 JPEG 送到网页 canvas。诊断显示原生 CDP 建连成功，但连续帧为 1280×693，metadata 为 1382×748；固定 1280×720 的 FrameHub 拒绝这些帧后约两秒降级为截图。因此约 **6.16 帧/秒是降级截图的结果**，不能当作 JPEG 直传技术的上限。

12.012 秒复测记录：JPEG 解码 p50 8.2ms，发送到绘制 p50 12ms，样本像素时间戳到绘制 p50/p95 为 64/90ms；点击和中文输入回执约 60/82ms，同会话和关闭后无所属残留通过。像素时钟法只对该带时间戳样本成立，不与其他页面 HTTP 回执口径直接比较。

报告分别为 `%TEMP%/mediacrawler-jpeg-direct-ebw041he/result.json` 与 `%TEMP%/mediacrawler-jpeg-direct-sjhhq0q5/result.json`。第二份进程树 CPU 混入 Taskmgr，不能使用其中 23.7% 总 CPU 做路线效率比较。主任务结束该候选试验，继续原生标签页捕获集成。

## 解释边界

“原生标签页捕获”表示浏览器内部捕获/编码标签画面，经 RTC 传给工作台；不表示目标网页 DOM 原生嵌入工作台，也不表示引入 Electron。输入、登录和任务仍需同一会话与原控制屏障。

独立样本尚未证明工作台的切页、隐藏、降级、会话释放、权限交互或真实平台加载表现。生产集成必须验证上述生命周期，再以持续采样与最低分段统计判断至少 30 帧/秒目标；如果只在独立试验达到，仍不能声明交付目标完成。

当前代码职责以[浏览器架构](../architecture/browser-workspace.md)为准，历史 JPEG/Python RTC 初次测量见[前一阶段记录](2026-09-07-rtc-performance.md)。
