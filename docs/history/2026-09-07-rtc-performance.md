# 2026-09-07 RTC 双模式本机测量

> 文档类型：历史执行快照
> 来源：本轮主任务独占复测；原始报告 `%TEMP%/mediacrawler-install-check/rtc-performance-results.json`。

## 环境与样本

Windows 本机纯网页工作台；采集视口 1280×720，接收网页 1440×900。样本是包含动态 canvas 与 video 的长页面，使用同一 Chromium 会话。测量期间没有其他本轮测试浏览器并发，不能排除用户其他系统负载。

这组测量在画面尺寸修复之后执行。此前误降级为源截图时约 2.6 帧/秒，不能把该值理解为 WebRTC 技术本身的上限。

## 实测结果

| 指标 | 结果 | 解释 |
| --- | --- | --- |
| RTC 接收画面 | 51 帧 / 10.031 秒，约 **5.08 帧/秒** | 配置目标 20；未达到目标 |
| RTC 源帧输出 | 74 帧 / 11.078 秒，约 6.68 帧/秒 | 源侧统计，不等于接收端解码帧率 |
| RTC 采集次数 | 72 次 / 11.078 秒 | 采集次数与输出帧不是同一指标 |
| 低刷新接收 | 16 帧 / 10.016 秒，约 **1.60 帧/秒** | 配置目标 2 |
| 后端进程 CPU：RTC | `(18.125 − 10.96875) / 11.078`，约 **64.6% 单逻辑核** | 仅后端进程 CPU 时间，不是整机占用 |
| 后端进程 CPU：低刷新 | `(19.734375 − 19) / 10.079`，约 **7.3% 单逻辑核** | 与 RTC 采用同类口径 |
| 后端 RSS | RTC 约 114 MiB，低刷新约 75 MiB | 进程常驻内存，不包含全部 Chromium/接收端开销 |
| 五次点击到本地页面 HTTP 回执 | 562 / 594 / 609 / 922 / 1000 毫秒 | 不是点击到新画面显示的端到端延迟 |

这份结果证明本机样本的实时与低刷新路径可测量，不能宣称“流畅目标已完成”，也不能承诺固定 20 或 60 帧/秒。采集、编码、传输、解码和页面响应需要分别分析。

## 功能证据与未完成项

真实本地 Chromium 的 WebRTC 接收、中文输入、长页面持续 screencast、切换截图后同 PID 均已验证。预览、浏览器、生命周期三组共 20 项测试通过。前端另完成桌面、笔记本、手机深浅主题矩阵及设置流程检查。这些功能证据不替代上述性能结果，也不代表真实网站登录或下载验收。

测量后曾出现一次最终关闭会话超过 30 秒。修复了可复现的取消污染：RTC 和整个浏览器清理共用受保护的关闭任务，页面/请求断开不会取消已经开始的清理，完成后从会话列表移除。独立 Python / Chromium 接收者累计 45 轮切换关闭正常；完整网页脚本最终复测退出码 0，API 会话列表为 0。原始偶发超时未能在独立复现中完全归因，以上是已验证的修复与复测范围。

## 最终复测

在上述关闭保护及合成器源帧限流后，用相同完整网页脚本再测，原始报告为 `%TEMP%/mediacrawler-install-check/rtc-performance-final-results.json`：

- RTC：54 帧 / 10.109 秒，约 **5.34 帧/秒**；源输出 81 帧 / 11.938 秒，约 6.79 帧/秒。
- 低刷新：15 帧 / 10.015 秒，约 **1.50 帧/秒**，设置仍为 2。
- 后端进程 CPU：RTC 约 50.0% 单逻辑核，低刷新约 4.3%；区间末工作集分别约 80.7 / 59.5 MiB，不含浏览器进程。
- 五次点击至页面 HTTP 回执：797 / 1563 / 5625 / 1250 / 3407 毫秒，响应波动较大，仍不能宣称流畅交互已验收。
- 实际 video 解码、小目标点击、中文、截图点击、滚轮、自动偏好、模式切换与隐藏后资源发现均通过；控制和资源连接各一个，无页面脚本异常，最终会话清理成功。

两次复测都未达到 20 帧/秒目标。源帧限流减少不需要的 JPEG，但没有据此取得足够证据宣称高帧率或低延迟目标完成。低刷新模式是明确的省资源选择；真实网站仍需另外验收。
